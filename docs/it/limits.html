Limiti

Cosa non offre Codex Council.

Council è un workflow consultivo. Il verdetto aiuta a strutturare una decisione; non sostituisce test, verifiche browser, security review o la tua responsabilità sul risultato.

Vincoli noti

Leggi le evidenze, non solo il verdetto.

  • Un solo modello Codex. Il council usa prompt di ruolo isolati, non provider o famiglie di modelli indipendenti.
  • Output consultivo. Un verdetto build non è un'approvazione alla produzione né una prova di correttezza.
  • Servono evidenze browser. Il comportamento della UI è verificato solo quando il flusso rilevante viene eseguito in un browser reale.
  • Le stime sono euristiche. I report locali sui token aiutano a pianificare; non sono dati di fatturazione, quota o risparmio misurato.
  • Expanded è esplicito. Il margine maggiore non parte senza la tua conferma.
  • Decision Runtime è sperimentale. La vista shadow non è autorevole; artefatti e verdetti originali restano la fonte di verità.

Privacy e stato

Anche lo stato locale richiede attenzione.

Scaffold di sessione, stime, prompt, output, statistiche, cronologia e override degli alter possono contenere contesto di progetto. Prima di pubblicare un repository, verifica che .codex-council/ sia ignorata e non committata. 

# Controlla gli artefatti runtime locali prima di pubblicare.
git status --short
find . -name '.codex-council' -o -name '.DS_Store' -o -name '__pycache__'

Decision Runtime

Una vista opzionale, mai l'autorità.

Opt-in

Nessuno shadow viene proiettato finché non lo richiedi. La funzione è locale e spenta di default.

Non autorevole

Lo stato shadow mancante o non sano viene ignorato. Sessione e verdetto salvati restano autorevoli.

Resta sensibile

I dati shadow sono stato locale, non evidenza cifrata. Proteggili come la sessione sorgente.

Da dove arriva

Ispirato a LLM Council, adattato a un solo ambiente Codex.

Il pattern arriva da karpathy/llm-council e llm-council.dev. Codex Council conserva la review multi-prospettiva, ma usa prompt isolati dentro Codex senza rivendicare diversità tra modelli indipendenti.
