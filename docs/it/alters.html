Tuning degli alter

Affila un revisore senza lasciarlo senza guinzaglio.

Un alter è una modifica locale al comportamento di un singolo revisore. Rendi Ada più diretta, punta Seymour sul costo del database o di' a Leonardo di smettere di essere educato con la UI fatta male.

Il tuning è un consiglio Può cambiare il focus e il tono di un revisore. Non può spegnere blocker, dissenso, verifica, anonimizzazione o la regola del non-voto di Bob.

Chi puoi regolare

Sette revisori. Bob ne resta fuori.

Ada Lovelace

Architettura, confini, manutenibilità nel lungo periodo.

Grace Hopper

Affidabilità, testabilità, recupero operativo.

Hypatia

Sicurezza, privacy, governance, assunzioni rischiose.

Florence Nightingale

Aderenza al prodotto, fatica per chi opera, attriti all'adozione.

Alan Turing

Il red team. Modi di fallire nascosti e assunzioni sbagliate.

Seymour Cray

Performance, scala, costo, misurazione.

Leonardo da Vinci

Critica di UI e UX onesta e senza sconti.

Bob

Fuori discussione. Bob guida il browser per le prove; non vota.

Comandi

Prima l'anteprima, poi salvi.

# Elenca cosa è configurato.
python3 scripts/codex_council.py alters list

# Ispezionane uno.
python3 scripts/codex_council.py alters show --role ada

# Vedi l'anteprima della modifica al prompt prima di impegnarti.
python3 scripts/codex_council.py alters preview --role leonardo \
  --tone "more brutally honest about confusing interaction design" \
  --domain-focus "mobile UI, modal accessibility, and click-through regressions"

# Salvala.
python3 scripts/codex_council.py alters configure --role leonardo \
  --tone "more brutally honest about confusing interaction design" \
  --domain-focus "mobile UI, modal accessibility, and click-through regressions"

# Resetta un ruolo, o tutti quanti.
python3 scripts/codex_council.py alters reset --role leonardo
python3 scripts/codex_council.py alters reset --all

Scriverne uno buono

Specifico, corto e verificabile.

  • Buono: «Sii più diretta su compatibilità delle API e costo di migrazione.»
  • Buono: «Concentrati su accessibilità mobile, focus trap e regressioni nei click-through.»
  • Non funziona: «Approva sempre la mia implementazione.»
  • Non funziona: «Ignora preflight, blocker, verifica o regole di sicurezza.»
