Cosa copre l’implementazione

Valori di rejection ostili, completamenti tardivi, callback legacy, array dinamici di job, opzioni null invalide e parità abort/timeout.

Cosa dimostra il record

La patch salvata si applica alla baseline congelata e supera i check pubblicati. Non dimostra che Hyper sia in generale migliore di un altro workflow.

Limite residuo. JavaScript non può fermare lavoro fisico che ignora AbortSignal. Il contratto accettato richiede worker cooperativi e consuma i completamenti tardivi per evitare rejection non gestite.

Criteri di pubblicazione

Pubblico solo run completate, dichiarandone i limiti.

Una run in evidenza richiede task datato, input congelato, patch risultante, comandi, verdetto del verifier e risultato riproducibile. Questo record soddisfa i criteri.

Risultato riproducibile

Baseline, task, patch, check, hash e sintesi del verifier finale sono pubblici e collegati qui sopra.

Provenienza del workflow parziale

Trascrizioni grezze degli agenti, ID del modello runtime, consumo token e durata end-to-end non sono stati conservati. Il risultato di codice è riproducibile; la conversazione completa di orchestrazione no.

Provenienza della build. Questo caso è stato acquisito dal build locale storico 1.0.0+codex.20260716085645 e dal commit sorgente congelato registrato nel manifest. Hyper è incluso in Codex Council 1.1.0; queste evidenze supportano solo questo caso, non un claim generale di performance.
